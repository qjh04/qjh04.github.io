九个常用设计模式

2025-11-05 · 4 min · 1.1k words

常见设计模式详解（9个高频面试模式）

包含：Singleton、Factory、Proxy、Decorator、Adapter、Observer、Strategy、Builder、Chain of Responsibility

🧱 1. 单例模式（Singleton）

意图：确保一个类只有一个实例，并提供全局访问点。

结构

  • 私有构造函数
  • 静态实例（懒汉 / 饿汉）
  • 全局访问方法

示例（Java）

优点

  • 全局唯一，节省资源。

缺点

  • 测试困难、隐藏依赖。

面试要点

  • 线程安全实现；序列化与反射破坏；懒汉 vs 饿汉。

⚙️ 2. 工厂模式（Factory）

意图：封装对象创建，使客户端与具体类解耦。

分类

  • 简单工厂（非GoF）
  • 工厂方法
  • 抽象工厂

示例（工厂方法）

优点

  • 解耦创建逻辑。

缺点

  • 增加类复杂度。

面试要点

  • 区分简单工厂、工厂方法、抽象工厂。

🧩 3. 代理模式（Proxy）

意图：控制访问目标对象，增强或延迟其行为。

结构

  • Subject 接口
  • RealSubject（真实对象）
  • Proxy（代理对象）

示例

优点

  • 控制访问、延迟加载。

缺点

  • 增加间接层。

面试要点

  • 区分 Proxy / Decorator / Adapter。

🎨 4. 装饰者模式（Decorator）

意图：在不修改类的情况下动态添加功能。

结构

  • Component（接口）
  • ConcreteComponent
  • Decorator（包装类）

示例

优点

  • 灵活扩展功能。

缺点

  • 类层级复杂。

面试要点

  • 动态增强 vs 继承。

🔌 5. 适配器模式（Adapter）

意图：使原本接口不兼容的类可以一起工作。

结构

  • Target（目标接口）
  • Adaptee（被适配类）
  • Adapter（适配器）

示例

优点

  • 复用旧代码。

缺点

  • 只解决接口不匹配问题。

面试要点

  • 区分 Adapter vs Facade。

📡 6. 观察者模式（Observer）

意图：对象间一对多依赖，当主题变化时通知所有观察者。

结构

  • Subject（主题）
  • Observer（观察者）

示例（Python）

优点

  • 低耦合，动态订阅。

缺点

  • 通知链复杂，易内存泄露。

面试要点

  • 区分 Observer vs Pub/Sub。

🧠 7. 策略模式（Strategy）

意图：定义一系列可互换算法，运行时可选择。

结构

  • Strategy 接口
  • ConcreteStrategy（实现不同算法）
  • Context（持有策略引用）

示例

优点

  • 避免复杂 if/else。

缺点

  • 策略过多时管理复杂。

面试要点

  • 与 Command / Factory 区别。

🏗️ 8. 建造者模式（Builder）

意图：一步步构建复杂对象，分离构建过程与表示。

结构

  • Builder / ConcreteBuilder
  • Director（可选）
  • Product

示例（Java 链式）

优点

  • 可读性好，灵活构建。

缺点

  • 增加类数量。

面试要点

  • 与 Factory 区别：Builder 注重“过程”，Factory 注重“结果”。

🔗 9. 责任链模式（Chain of Responsibility）

意图：让多个对象有机会处理请求，形成处理链。

结构

  • Handler（抽象处理者）
  • ConcreteHandler（实现处理逻辑）

示例

优点

  • 解耦请求发送者和接收者。

缺点

  • 调试链条困难。

面试要点

  • 区分 Chain / Observer / Command。
