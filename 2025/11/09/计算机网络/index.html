网络基础

HTTP

一、什么是HTTP

概念

HTTP 是超文本传输协议，也就是HyperText Transfer Protocol。

协议：多个计算机之间通信、控制的规约。
传输：从A到B
超文本：文本、图片、视频、音频的复杂组合

状态码

2XX成功
301:永久重定向 302:临时重定向
400:用户请求有问题 403:用户权限不足 404:服务器没有该资源 405:请求方法出错
500:服务器报错 502:服务器作为网关访问后端服务器出错 503:服务器暂忙 504：超时

二、各版本HTTP特点

HTTP1.0

基础版本，没有长连接复用TCP，优点简单。可拓展、跨平台、应用广泛

HTTP1.1

在1.0的基础上增加长连接可复用TCP，且拥有以上优点，缺点就是无状态、明文传输不安全、队头阻塞

队头阻塞：虽然HTTP1.1有管道网络传输即请求发送后不用等待响应可以继续发，但没有应用，所以在HTTP1.1的情况下，发送一个请求后，必须等服务端响应后才嫩发送第二个请求，如果服务端存在阻塞，也会连带阻塞第二个请求。

HTTP2

相较于版本1引入了相同请求头可压缩，数据以二进制流传输虽然不利于人类阅读但利于计算机运算，服务器可主动推送资源，但其中最牛的还属在同一个TCP连接中引入多个Stream。每一个Stream可以作为一个请求发送，在服务端接收请求的时候可以按Stream处理并响应，可以做到按不同Stream顺序发送响应在宏观层面达到一种并发传输的效果。这虽然解决了HTTP层面的队头阻塞即请求智能一个一个发，但引来了TCP层的队头阻塞，因为TCP层是按顺序等待包到来的，如果1 2 3 4同时发送，1到了，3 4到了，但是2没有到，还是需要2重传到达之后才能读取3 4导致TCP队头阻塞，即使数据到了，也不能读取。

HTTP3

HTTP3将传输层协议从TCP改成了UDP，彻底解决队头阻塞问题，不再需要按顺序等待数据到达在读取，其中如果有数据丢失也是按相应的Stream进行重传，并不会影响其他流。更快的连接建立，其他两个版本的TCP与TLS是分别建立连接，而HTTP3只需要一个RTT就能建立连接判断双方的StreanID即可。高效的连接迁移，其他两个版本需要两个ip两个端口号的四元组才能标识一条连接，而QUIC只需要StreamID即可。

三、HTTP与HTTPS

区别

1、HTTPS在HTTP与TCP之间加入TLS/SSL层加密
2、HTTPS可以防范监听、篡改、伪造
3、HTTP端口号为80, HTTPS端口号为443

HTTPS的连接过程

首先进行TCP三次握手，然后进行TLS/SSL层的四次握手

1、客户端（生成随机数、确定TLS/SSL版本、加密算法）
2、服务端（生成随机数、确定TLS/SSL版本、加密算法、发送CA证书）
3、客户端（生成随机数，验证CA证书合法性、根据CA中的公钥加密三个随机数）
4、服务端（根据私钥解密客户端发送的加密后的三个随机数、后续都拿这个加密后的串作为密钥）

整个过程对称加密、非对称加密都用到了，因为非对称加密性能较差且如果私钥泄密后果不堪设想，对称加密性能高且需要仅双方知道。

四、与其他协议的关系

RPC

RPC（远程过程调用）并不是协议是一种思想，类似gRpc才是一种协议，并且RPC出的比HTTP还要早。在早期的CS架构中，一个客户端只需要连接自家公司的服务器即可只用rpc，到后来browse兴盛BS架构逐渐成为主流，且HTTP、RPC逐渐趋于同化，HTTP用户前端到后端通信，RPC用于后端内部服务间通信

WebSocket

WebSocket支持服务器主动推送资源，而不需要长轮询或者不断轮询。
