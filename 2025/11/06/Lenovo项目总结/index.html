2025-11-06 · 16 min · 4.1k words

项目复盘：

一、项目亮点总结

亮点1：企业&认证机构一体化注册流程

1. 业务背景与问题

问题：

  • 企业注册流程复杂，需要填写大量信息，用户容易出错
  • 信息填写过程中没有保存机制，一旦出错需要重新填写，用户体验差
  • 因信息错误导致的提交失败率高，影响业务效率
  • 企业用户和认证机构用户需要访问不同的数据，缺乏权限隔离机制

2. 解决方案与技术实现

技术方案：

  • 草稿保存机制：设计并实现了信息草稿多次保存功能，支持用户随时保存填写进度
  • 信息校验机制：在提交前进行多维度信息校验，提前发现并提示错误
  • 权限隔离：集成Spring Security框架，实现基于角色的权限控制（RBAC），确保企业用户和认证机构用户只能访问各自权限范围内的数据

技术栈： Spring Security、Spring Boot、PostgreSQL

3. 解决效果与结果

结果：

  • 将因信息错误导致的提交失败率降低30%
  • 提升了用户填写体验，减少重复填写工作
  • 实现了不同端用户数据访问的安全隔离，保障了数据安全

亮点2：回收-再生-利用三企业全链条交易数据追溯系统

1. 业务背景与问题

问题：

  • 需要实现从原料回收到成品利用的完整数据链路追溯
  • 回收企业、再生企业、利用企业之间的交易数据缺乏关联机制
  • 无法快速定位任意环节的交易数据，追溯效率低
  • 需要支持企业自有系统与平台的数据对接

2. 解决方案与技术实现

技术方案：

  • 双重标识机制：创新性地设计了”对应码+追溯码”双重标识机制
    • 回收企业生成对应码（CTI开头+9位随机字符）
    • 再生企业生成追溯码（64位随机字符串）
    • 利用企业生成新的追溯码（64位随机字符串）
  • API接口设计：基于Spring Boot构建了RESTful API接口，支持企业自有系统对接
  • Web界面填报：开发了Web界面填报功能，支持双模式数据录入
  • 数据校验引擎：设计了包含重量校验、GPS位置验证、再生含量公式计算等10+项业务规则的数据校验引擎
  • 数据安全：集成SM4国密算法，对敏感数据进行加密存储

技术栈： Spring Boot、PostgreSQL、SM4加密算法、MyBatis-Plus

3. 解决效果与结果

结果：

  • 实现了从原料回收到成品利用的完整数据链路追溯
  • 通过追溯码可以快速定位任意环节的交易数据，追溯效率提升60%以上
  • 支持企业自有系统无缝对接，提升了数据录入效率
  • 通过多维度数据校验，确保了交易数据的准确性与合规性

亮点3：运营端首页数据看板

1. 业务背景与问题

问题：

  • 运营人员需要实时了解业务运营情况，缺乏数据支撑
  • 关键业务指标分散在各个模块，无法集中查看
  • 数据查询效率低，影响运营决策效率
  • 缺乏数据可视化展示，数据理解困难

2. 解决方案与技术实现

技术方案：

  • 数据聚合：基于MyBatis-Plus与PostgreSQL，设计并实现了数据聚合查询
  • 实时数据展示：开发了9个关键业务指标的实时数据查询接口
    • 交易总量
    • 认证企业数
    • 用户总量
    • 材料回收情况
    • 等其他5个指标
  • 可视化展示：通过前端图表组件实现数据的可视化展示
  • 性能优化：通过数据库索引优化和查询优化，提升数据查询效率

技术栈： MyBatis-Plus、PostgreSQL、Spring Boot、前端图表组件

3. 解决效果与结果

结果：

  • 提供了9个关键业务指标的实时可视化展示
  • 运营人员可以快速了解业务运营情况，提升了决策效率
  • 数据集中展示，减少了数据查询时间
  • 通过数据可视化，提升了数据的可理解性

亮点4：企业范围认证模块

1. 业务背景与问题

问题：

  • 企业认证流程复杂，涉及多个环节和角色
  • 需要支持多级材料提交，材料管理困难
  • 认证机构需要审核企业提交的材料，缺乏审核流程
  • 认证状态变更需要及时通知相关用户，缺乏消息通知机制

2. 解决方案与技术实现

技术方案：

  • 认证申请功能：设计并实现了企业认证申请功能，支持企业提交认证申请
  • 多级材料提交：实现了多级材料提交功能，支持企业分批次提交认证材料
  • 认证机构审核：开发了认证机构审核功能，支持审核人员审核企业提交的材料
  • 消息通知机制：实现了消息通知功能，当认证状态变更时，自动通知相关用户
  • 全流程管理：实现了从申请到审核到通知的完整流程管理

技术栈： Spring Boot、PostgreSQL、MyBatis-Plus、消息通知机制

3. 解决效果与结果

结果：

  • 完成了企业范围认证模块的全流程开发
  • 支持企业多级材料提交，提升了材料管理效率
  • 实现了认证机构审核功能，规范了认证流程
  • 通过消息通知机制，及时通知用户认证状态变更，提升了用户体验

亮点5：原料信息变更的多级审批工作流

1. 业务背景与问题

问题：

  • 原料信息是关键数据，变更需要严格审批
  • 需要支持多级审批流程，确保数据变更的合规性
  • 需要支持依次审批机制，确保每个审批环节都经过审核
  • 需要支持”一票否决”机制，任何一级审批不通过，整个流程终止

2. 解决方案与技术实现

技术方案：

  • 多级审批工作流设计：设计并实现了多级审批工作流引擎
  • 依次审批机制：实现了依次审批功能，确保审批流程按顺序进行
  • 一票否决机制：实现了”一票否决”功能，任何一级审批不通过，整个流程终止
  • 审批状态管理：实现了审批状态的管理和跟踪，支持审批流程的实时查询
  • 审批通知机制：实现了审批通知功能，及时通知相关人员审批状态变更

技术栈： Spring Boot、PostgreSQL、工作流引擎、状态机设计

3. 解决效果与结果

结果：

  • 实现了原料信息变更的多级审批工作流
  • 通过依次审批机制，确保了每个审批环节都经过审核
  • 通过”一票否决”机制，确保了关键数据变更的合规性
  • 规范了数据变更流程，降低了数据错误风险

总结

以上5个亮点都遵循了”问题-解决方案-结果”的结构，清晰地展示了：

  1. 业务理解能力：能够识别业务问题
  2. 技术实现能力：能够用技术解决业务问题
  3. 结果导向思维：关注解决方案带来的实际效果

这种表达方式在面试中更容易被理解，也更能体现你的问题解决能力和业务理解能力。

关键点总结

  1. 回收企业：

    • 生成对应码（识别码）：格式 CTI + 9位随机字符
    • 存储表：transaction_data_recycle

  3. 利用企业：

    • 接收再生企业的追溯码
    • 生成新的追溯码：64位随机字符串
    • 存储表：transaction_data_main（企业类型=3）

  4. 追溯查询：

    • 利用企业：使用 traceabilityCode 查询
    • 再生企业：使用 materialCode（实际是追溯码）查询
    • 回收企业：使用 idCode（对应码）查询

    • 回收企业 → 再生企业：通过对应码关联
    • 再生企业 → 利用企业：通过追溯码关联
    • 每个环节都可以向上追溯完整的交易链
